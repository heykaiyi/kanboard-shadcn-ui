# Shadcn — Kanboard のための shadcn/ui テーマ

[English](README.md) · [繁體中文](README.zh-TW.md) · **日本語**

Kanboard のインターフェイス全体を [shadcn/ui](https://ui.shadcn.com) のデザイン言語で
作り直し、同梱の Font Awesome グリフを [HugeIcons](https://hugeicons.com) に差し替えます。
ライトとダークの両方に対応し、各ユーザーが Kanboard で選んだテーマ設定にそのまま従います。

**コアファイルは一つも変更せず、テンプレートも一つも上書きしません**。だから Kanboard は
このテーマの下で問題なくアップグレードできます。ほとんどはスタイルシートだけで、唯一の例外が
サイドバー — Kanboard が元から用意しているフックへプラグインが描き込むマークアップです。

![ダッシュボード: ブランドのロックアップ付きサイドバー、パンくず、コマンド検索、統計タイル、プロジェクト一覧](docs/screenshots/dashboard.jpg)

## インストール

Kanboard のプラグインは `plugins/` 配下のディレクトリで、そのディレクトリ名がプラグインの
名前空間になります。つまりどの方法で入れるにせよ、これは `plugins/Shadcn` に置く必要が
あります。

**git から** — 後から更新しやすいのはこちら:

```
cd /path/to/kanboard/plugins
git clone https://github.com/heykaiyi/kanboard-shadcn-ui.git Shadcn
```

以降は `git -C plugins/Shadcn pull` で次のバージョンが取れます。

**zip から** — シェルのないホスト向け:

```
unzip Shadcn-x.y.z.zip -d /path/to/kanboard/plugins
```

アーカイブには `Shadcn/` ディレクトリが既に含まれているので、`plugins/` にそのまま展開すれば
済みます。同じファイルは `PLUGIN_INSTALLER` を有効にしたインスタンスの
**設定 → プラグイン → URL からインストール** でも使えます。Kanboard がアーカイブを
ダウンロードし、上のコマンドとまったく同じように `plugins/` へ展開します。

あとはページを再読み込みするだけ。Kanboard は次のリクエストでプラグインを認識します。
消すキャッシュもなければ、走らせるマイグレーションもありません。各ユーザーが既に選んでいる
**設定 → プロフィール → テーマ**（ライト／ダーク／自動）がそのままパレットを決め、何も
設定していないインストールは出荷時のままの見た目になります。

自分のものにするなら **設定 → 外観**（`/settings/brand`）へ — 下記参照。

アンインストールはディレクトリを削除するだけです。外側には何も触れません。ブランディングは
Kanboard 自身の `settings` テーブルに、アップロードした二つの画像は `data/files/shadcn/` に
あるので、プラグインを外してもそれらは残り、戻せばまた見つかります。

### 必要環境

Kanboard 1.2.0 以降と、2023 年以降のブラウザ — `oklch()`、`color-mix()`、`:has()` を全体で
使っています。それより古いブラウザではサイドバーがページ上部の普通のブロックに退化しますが、
それは元々の縦積みレイアウトそのもので、問題なく使えます。

## 仕組み

すべては Kanboard についての二つの事実の上に成り立っています。

**1. Kanboard は元から CSS カスタムプロパティでテーマを組んでいる。**
`assets/css/src/themes/*.css` が約 90 個の変数
（`--button-primary-background-color`、`--dropdown-border-color` …）を定義し、他の約 60 個の
コアスタイルシートがそれを消費します。`Assets/css/tokens.css` は shadcn のトークンセットを
宣言し、そのうえで *Kanboard の変数すべてをそのトークンで定義し直します*:

```css
--primary: oklch(0.205 0 0);          /* shadcn */
--button-primary-background-color: var(--primary);   /* ブリッジ */
```

このブリッジ一枚で、ボード、分析、ガント、カレンダー、そしてこのプラグインが名指ししていない
すべての画面が張り替わります。

**2. プラグインのスタイルシートは最後に読み込まれる。**`app/Template/layout.php` は
`template:layout:css` フックを、ベンダー CSS の後、テーマ CSS の後、インスタンスの
スタイルシートの後に描画します。だから同じ詳細度のルールが `!important` なしで勝てます:

```
vendor.min.css → light|dark|auto.min.css → customCss() → [tokens, components, icons] → [theme-dark|auto]
```

ダークトークンだけは静的ファイルにできません — それはユーザーごとの選択だからです。
そこで `Template/layout/head.php` が `template:layout:head` フックで選び分けます。

**3. `template:layout:top` は `<body>` の内側、すべての先頭に描画される。**
サイドバーはそこに入ります。つまり Kanboard 自身の `<header>` と
`<section class="page">` の兄弟になる — 追加であって、上書きではありません。

### header からサイドバーを作る

Kanboard には作り直すべきグローバルナビゲーションがありません。あるのは header です:

```html
<header>
  <div class="title-container">…            ページタイトル
  <div class="board-selector-container">…   別のプロジェクトへ移動
  <div class="menus-container">…            通知、新規、ユーザー
```

`sidebar.css` は `<body>` をグリッドにし、`header { display: contents }` を指定します。
これで `<header>` のボックスが消え、三つの div がそのグリッドに引き上げられます。以降は
それぞれをページのどこにでも置けます — ユーザーメニューはサイドバーのフッターへ、残りは
トップバーへ — しかも各自のマークアップ、各自の JavaScript、各自の拡張フックはそのままです。
何も複製せず、何も再実装していません。

ナビゲーション本体は Kanboard が提供できない部分なので、`Template/layout/sidebar.php` が
描画します: ダッシュボード、現在のプロジェクトのビュー（実際にインストールされ、権限のある
ものだけ）、そしてユーザーのプロジェクト一覧です。`template:layout:top` は引数なしで描画
されるため、現在のプロジェクトと現在のルートは `Helper/SidebarHelper.php` が解決します。

`Assets/js/sidebar.js` はこのテーマが同梱する唯一のスクリプトです。サイドバーを 3rem の
アイコンレールに畳み、その選択を `localStorage` に覚え、768px 未満ではページに被さる
ドロワーに変え、Cmd/Ctrl-B を割り当てます — 入力中は無視するので、エディタから「太字」を
奪うことはありません。状態は `<body>` が解析される前、`<head>` の時点で `<html>` に書くので、
畳んだサイドバーが読み込み時に一瞬開くことはありません。

### テンプレートに触らずにアイコンを差し替える

Kanboard は `<i class="fa fa-cog">` を出力し、アイコンフォントで描きます。それらのクラス名の
半分はテンプレートに一度も現れません。`$this->url->icon('cog', …)` に渡される文字列だからです。
そこでテンプレートを書き換える代わりに、`icons.css` はマークアップを残したままボックスを
塗り直します:

```css
.fa-cog::before { content: none }
.fa-cog {
    background-color: currentColor;
    mask-image: url("data:image/svg+xml,…");   /* HugeIcons のパス */
}
```

アイコンは `color` と `font-size` を継承し、Font Awesome の修飾子はすべてそのまま効き
（`fa-2x`、`fa-fw`、`fa-spin`、`fa-rotate-90`、`fa-inverse`）、後から Ajax で挿入された
マークアップも JavaScript なしでスタイルが当たります。対応表にない `fa-*` クラスはそのままに
してあり、元のフォントで描画され続けるので、アイコンが消えることはありません。

対応させたアイコンは 138 個。コアが使うものすべてに加えて、サードパーティのプラグインが
よく使う Font Awesome 4 の名前も含みます。

## ブランディング

**設定 → 外観**（`/settings/brand`）、管理者のみ。八項目、しかも意図的に八項目だけです:

| | |
|---|---|
| **アプリケーション名** | サイドバーのマークの横のラベル、ログイン画面の見出し、そしてすべてのメールの送信者名。 |
| **タグライン** | サイドバーの名前の下の小さな一行。 |
| **アクセントカラー** | 16 進数を一つ、スウォッチで選ぶか直接入力。ボタン、リンク、サイドバーの現在項目、フォーカスの枠線、メールのヘッダー。ライトとダークで一度ずつ答えます。 |
| **セカンダリカラー** | 主役ではないコントロールの下地: トップバーの検索ボックスとベル、そして複数選択の中のチップ。こちらも二つの答え。 |
| **ロゴ** | PNG、JPG、GIF、WebP、SVG、1 MB まで。サイドバー、ログイン画面、すべてのメールの先頭に描かれます。 |
| **ロックアップ** | どこまで描くか: マークだけ、マークと名前、あるいはマークと名前とタグライン。 |
| **マークのサイズ** | テーマが描く既定サイズの 50–200%。 |
| **ファビコン** | 同じ形式。空のままならロゴがタブアイコンとして使われます。 |

すべて任意です。空欄は同梱の既定値を意味するので、「リセット」と「一度も設定していない」は
同じ状態です。

![設定 → 外観: アプリケーション名、タグライン、各色のライトとダークの値](docs/screenshots/appearance-name-colors.jpg)

この画面は保存より先に答えを返します: スウォッチと 16 進数の欄は一つの値の二つの見え方で、
プレビュー行はその色をボタン、バッジ、リンクとして見せます — テーマが計算する黒か白かの
ラベル色も含めて。選んだ画像はアップロード前にその台座の中に描かれます。ロックアップと
マークのサイズにはもっと良いプレビューがあります: 画面の横に立っているサイドバー*そのもの*が
プレビューで、ラジオとスライダーに合わせてその場で変わります。これらはすべて
`Assets/js/branding.js` によるもので、どれも必須ではありません。JavaScript がなければ
スウォッチは単に送信されない二つ目の入力欄になるだけです。

![設定 → 外観: ライトとダークのライブプレビュー行、ロゴのロックアップとサイズ、ファビコン](docs/screenshots/appearance-logo-favicon.jpg)

### ロックアップとサイズ

すでにワードマークを含んでいるマークは、その横に名前を印字してほしくありません。名前こそが
主題であるインスタンスは、その下にタグラインを置いてほしくありません。だから三つの span は
常に描画され、選択は「不要なものを隠す」スタイルシート断片一つになっています — ブランドの
リンクが `aria-label` を持っている理由も、プレビューのコストが `<style>` 要素一つで済む理由も
ここにあります。メールだけは例外で、常に名前を載せます。画像だけの通知は、誰からの通知でも
ないからです。

**マークのサイズ**は長さではなく倍率です。それぞれの場所が自分の基準でマークを描き —
サイドバーでは 2rem、ログイン画面では 2.25rem — `--sc-brand-scale` がそのすべてを、一つの
サイズに潰すことなく動かします。サイドバーのブランド行は `min-height` なので、200% では
切り取られるのではなく行の方が伸びます。

### 四十色ではなく二色である理由

アクセントは `--primary`、`--sidebar-primary`、バッジの塗りに書き込まれ、その上に載る文字は
白と決め打ちするのではなく*計算されます* — 黒と白それぞれに対する WCAG コントラスト比の
大きい方です。だから淡いブランドカラーは、読めないボタンではなく濃い文字のボタンになります。
同じ守りがメール本文にも効いていて、リンクは白背景で 4.5:1 を超えるときだけアクセントを採用し、
超えなければ既定の青のままです。

セカンダリは、アクセントと張り合う二つ目のブランドカラーではありません。それは
`--secondary`、そのページの主役の動作*ではない*コントロールの下地です: トップバーの検索
ボックスとベル、そして複数選択の中のチップ。前景色は同じ方法で計算し、検索ボックスのラベルは
灰色に固定するのではなくその前景色を下地の方へ混ぜて作るので、濃い色にしてもテーマ既定の
ほぼ白にしても読めるままです。

この二色はそれぞれ二度答えます — ライトパレットに一度、ダークパレットに一度 — 白の上でよく
読める色が、夜によく読める色とは限らないからです。ダーク欄を空のままにすると「夜も同じ色」を
意味し、それは二つの答えが存在する前のすべてのインスタンスの状態そのものです。誰がどちらの
パレットを見るかはその人の **設定 → プロフィール → テーマ** の問題で、ここで決まるのは
それぞれがどう見えるかだけです。ダークの答えは、テーマ自身のダークトークンとまったく同じ
場所に出力されます: 「ダーク」ならそのまま、「自動」なら `prefers-color-scheme` の内側、
「ライト」なら出力しません。

パレットの残りは導出のままです。トークンごとにピッカーを並べた設定画面は、醜いインスタンスを
作る方法であって、ブランドのあるインスタンスを作る方法ではありません。

### 画像の置き場所

`data/files/shadcn/`、他のすべてのアップロードの隣です — プラグインのフォルダはアップグレード時
に丸ごと置き換わりますし、まともなインストールではそもそも書き込み可能であるべきではありません。
そのディレクトリは HTTP から到達できないので、`BrandingController::image` が配信します。
このプラグインが追加する唯一の公開ルートです。ログイン画面にもマークがあり、そこではまだ
誰もサインインしていないからです。

すべての URL はアップロードごとに変わるハッシュを含みます。これで一年のキャッシュが安全に
なり、差し替えたロゴがメールでも実際に切り替わるようになります。Gmail は画像を URL で
キャッシュし、二度と取りに来ないからです。

アップロードされた SVG は、入口でスクリプトの有無を検査し、出口では `default-src 'none'` と
`nosniff` を付けて配信されます。

### Kanboard 自身のファビコンに勝つ

コアはこのプラグインが描画するフックのすぐ数行前で `adaptive-favicon.svg` を宣言していて、
ブラウザは SVG と PNG の両方を渡されるとどちらが後でも SVG を取ります。そこでラスター画像の
アップロードは PNG として宣言せず、プラグインが生成する要素一つの SVG に包んで SVG として
宣言します。`apple-touch-icon` は SVG をまったく見ないので、そちらには元のファイルを渡します。

### パレットごと差し替える

一色なら設定です（**設定 → 外観**）。パレット一式ならファイルです: `Assets/css/tokens.css` に
shadcn の "neutral" セットがそのまま入っています。
[ui.shadcn.com/themes](https://ui.shadcn.com/themes) の任意のテーマを `:root` ブロックに
貼り替えれば（ダークの値は `theme-dark.css` / `theme-auto.css` へ）、アプリケーション全体が
それに従います。他に編集は要りません — ただし設定で指定したアクセントはこれらのファイルより
後に出力されるので、そこで宣言された `--primary` には常に勝ち続けます。

### アイコンを差し替える

```
cd plugins/Shadcn
npm i @hugeicons/core-free-icons
node Tools/generate-icons.mjs
```

ジェネレータ冒頭の `MAP` オブジェクトを編集します。キーは Font Awesome 4 の名前、値は
パッケージの `dist/esm` ディレクトリにある HugeIcons のモジュール名です。

## 補足と既知の未対応

- **タスクの色は捨てず、残している。** Kanboard は
  `.task-board.color-yellow { background-color: … ; border-color: … }` をインラインの
  `<style>` に書き出します。このテーマは*背景*と上・右・下の枠線だけを中和し、色は shadcn Card
  の左 3px のアクセントとして残します。色分けは一目で読めるまま、ボードを洗い流しません。
- **`.project-header` の float バグをここで直している。** Kanboard は設定ドロップダウンと
  ビュー切替を float させたまま clear しないので、既定の 26px の切替より背の高いものがあると
  ページ全体が横にずれます。ヘッダーは flex に変換しました。
- **第 1 回は全体の枠組み** — レイアウト、ヘッダー、サイドバー、ボタン、フォーム、メニュー、
  ダイアログ、テーブル、タブ、トースト。ボードとタスク詳細は一次対応: カードの外装、色の扱い、
  列ヘッダー。
- **第 2 回は既定のジオメトリのままだった五つの画面を作り直した** — コメントスレッドと
  アクティビティストリーム（float + `margin-left: 55px` をグリッドに置き換え、メッセージは
  32px のアバターの横のバブルに）、サブタスクのテーブル、FullCalendar のビュー、ガントの
  グリッド、c3 の分析チャート。
- **ベンダー CSS には読み込み順ではなく詳細度で勝つ。** FullCalendar とガントのプラグインは
  同じ `template:layout:css` フックに自分のスタイルシートを登録し、Kanboard は
  `DirectoryIterator` でプラグインディレクトリを走査するため順序はファイルシステム任せです。
  そこで彼らのルールを置き換えるものはすべて、置き換える相手より一段深く書いてあり
  （`.fc.fc-unthemed td`、`#gantt-chart .ganttview-block`）、どのプラグインが最後に読まれても
  勝ちます。
- **`!important` はチャートに一箇所だけ。** c3 は系列ごとの色をインラインの `style` 属性に
  書くので、他からは手が届きません。六つの `!important` 宣言は `--c3-series` カスタム
  プロパティから `stroke` / `fill` を設定し、その上のインデックス規則がそれを `--chart-1`…
  `--chart-5` に向けています。パレット自体は `tokens.css` にあります。
- **カレンダーの予定とガントのバーはタスクの色を保つ**、ボードとまったく同じです。どちらも
  インラインスタイル由来なので、作り直すのはジオメトリとラベルだけ — ラベルは FullCalendar の
  白から濃い文字に変わります。Kanboard のパステル調のタスク色に本当に必要なのはそちらです。
- **第 3 回でサイドバーを追加。** shadcn の `sidebar-07`、アイコンまで折りたためる形で、
  パンくずと三つのメニューしか載せなくなったトップバーは拡大しました。Checkbox と Radio Group は
  `accent-color` をやめて実際に描画するコントロールになり、Dialog は両軸で中央に、768px 未満
  では下端にドックして Drawer になります。
- **サイドバーは fixed であってグリッドアイテムではない。** 通常フローではドキュメントと同じ
  高さになるため、ウィンドウより高いページではナビが流れて消え、ユーザーメニューが*画面*の
  下端ではなく*ページ*の下端に行ってしまいました。グリッドの一列目は明示的なトラックとして
  残してあり、それが固定列とコンテンツの重なりを防いでいます。
- **ダイアログのフッターは本物のボタン二つ組。** `submit-buttons.js` は
  `[Save] " or " [cancel]` を出力します — ボタン、テキストノード、リンクです。リンクは
  outline Button に昇格させて動作の前に移し、shadcn の `DialogFooter` に合わせました。
  余った " or " は `font-size: 0` で潰しています。この二つは 3:7 でダイアログを埋め、
  キャンセルが先です。
- **ダイアログは一列フォーム**なので、フィールドはそれを埋めます。`form.css` はほとんどを
  70px / 150px / 300px / 400px に固定していて、どの幅でも右端がぎざぎざになります。必須
  フィールドは後ろに続く裸の `<span>*</span>` の分の場所を確保し、印がフィールドと同じ行に
  留まるようにしています。
- **閉じるボタンはタイトルと同じ行に座る。** `modal.js` は `#modal-header` を
  `#modal-content` の*上*のブロックとして描画するので、✕ がタイトルの上に一行を占めていました。
  フローから外すことで、shadcn の `DialogHeader` が置く位置に落ち着きます。
- **アスタリスクはラベルのもの。** `FormHelper` は `<label>`、`<input>`、
  `<span class="form-required">*</span>` を三つの兄弟として出力するため、印がコントロールの
  後ろに来ます — 全幅のコントロールならそれ自体が一行になってしまいます。その形が成立して
  いる場所ではラベルがアスタリスクを引き取り、余った span を落とします。成立しない場所では
  元の span をそのままにします。
- **ダイアログのフッターに `gap` はない。** 二つのコントロールの間の `" or "` は裸のテキスト
  ノードなので、flex コンテナはそれを order 0 の匿名アイテムに包みます — 最初の位置*と gap 一つ*
  を占め、行全体がフィールドより 8px 右にずれていました。代わりに margin で間を空け、今は
  すべての端が上のフィールドと揃います。
- **ダイアログのタイトル下の罫線は `h2` 自身の border** なので、閉じるボタンのための余白は
  `h2` の padding でなければなりません。`.page-header` に置くと、罫線がダイアログの端まで
  2.5rem 届かなくなります。
- **Kanboard が話す言語をそのまま話す。** すべての文字列は `t()` を通り、
  `Plugin::onStartup()` がそのリクエストの言語で `Locale/<language>` を読み込むので、各
  ユーザーの **設定 → プロフィール → 言語** に従います。ログイン画面の匿名訪問者には
  インスタンスの既定言語が使われます。辞書は `zh_TW`、`zh_CN`、`ja_JP` を同梱していて、この
  プラグインが追加する約 80 の文字列をカバーします。それ以外の画面上の文字は Kanboard 自身の
  その言語の翻訳から来ます。ファイルのない言語は英語の原文にフォールバックします — 未翻訳の
  文字列に対して Kanboard 自身がそうするのと同じ扱いなので、空欄になることも、読者が選んで
  いない言語が混ざることもありません。繁体字は台湾の語彙（專案、儲存、看板）、簡体字は大陸の
  語彙（项目、保存、看板）を使います。どちらも Kanboard 自身のファイルと合わせて一つの
  インターフェイスとして読めなければならないからです。Calendar と Gantt のプラグインは簡体字
  しか同梱していないため、それぞれの設定画面には各自の `zh_TW` ファイルが必要です — それは
  ここではなく、それらのプラグインの側にあります。
- **このテーマはフラット。** ドロップシャドウはすべて排しました。高さは枠線と面の色だけで
  表します。`--shadow-*` のスケールは `tokens.css` に残していますが `none` として定義して
  あるので、奥行きを戻すのは全コンポーネントを編集する話ではなく、そこの四行の変更です。
  コアが直接描いている影（ドロップダウン、ツールチップ、候補メニュー、ドラッグゴースト、
  モーダル）は名前を挙げて中和しています。
- **きれいな URL。** Kanboard はどちらの設定でもスラッグのルートを登録しますが、出力するのは
  `ENABLE_URL_REWRITE` が有効なときだけです — `config.php` を参照。`KANBOARD_URL` も合わせて
  設定する必要があります。そうしないと `UrlHelper::dir()` が `dirname(PHP_SELF)` から
  ベースパスを推測し、パス自体がルートである瞬間にそれは間違いになるからです。これはインスタンス
  側の設定であり、プラグインの一部ではありません。
- **第 4 回は入口を扱った。** ログインとパスワードリセットの画面は shadcn の `login-02` に
  なりました — 二列、ブランドマーク、中央寄せのフォーム、`lg` 未満で消えるカバーパネル。
  Kanboard はこれらを `no_layout` で描画するので、`<body>` には `.form-login` しかなく、
  レイアウト全体がそれにぶら下がります。カバーパネルは `body::after` で、マークアップは
  不要です。見出しは CSS の `content()` ではなく `template:auth:login-form:before` の
  テンプレートから来るので、`t()` を通ります。
- **本物のパンくず。** Kanboard は連結済みの文字列を `<h1>` に一つ置きます
  （"Project > Swimlane > Column"）。どんなスタイルシートもそれを分割できません。この経路は
  `SidebarHelper::getBreadcrumb()` でルートから再構築し、元のタイトルはグリッドから退場します。
- **すべてのダイアログは Sheet。** Kanboard は動的な画面すべてを一つの `#modal-box` に描画
  します。このテーマはその箱を右端にドックさせ、全高で、自分のスクロールを持たせます —
  タイトルは上に、フォームの操作は下に固定されるので、長いフォームはその両方の下をスクロール
  していき、保存ボタンが折り返しの下に埋もれません。768px 未満では同じ箱が下端に着いて Drawer に
  なります。通知パネルだけは違うシートですが、違うのは内側だけです: 埋めるフォームではなく
  眺めるリストなので、スクロールはリストが持ち、「すべて既読にする」が下に移ります。すべての
  モーダルはその唯一の `#modal-box` を共有し、見分ける手掛かりが何もないため、
  `Assets/js/modal.js` は開いたリンクが通知のものだったときに `<html>` へ印を付けます — 判定は
  href ではなく `.notification` のラッパーで行います。URL リライトが有効になると href に
  コントローラ名が残らないからです。
- **スクリムは両パレットとも 80% の黒。** シートはページを退場させます。10% の薄がけでは
  そう言えていませんでした。クリックすれば必ず閉じます: コアも同じ挙動を持っていますが、
  フォーム内で change イベントが一度でも起きると拒否します — `isFormDirty` は最初のキー入力で
  立ち、二度と下りないので、それ以降の出口は ✕ だけになっていました。
- **すべてのパスワード欄に表示／非表示のコントロールがある。** `Assets/js/password.js` が
  input をその場で包むので、テンプレートは一つも上書きせず、シートが後から読み込む欄も
  オブザーバが拾います。送信時にはフィールドが `type="password"` に戻ります — 平文が見えている
  パスワードを、ブラウザは保存するか尋ねてくれません。
- **ドキュメントのリンクはインスタンスの外へ出る。** docs.kanboard.org を自分のタブで開きます。
  アプリケーションに同梱されている写しは同じサイトのスナップショットで、常にそれより古いものです。
- **プロジェクトを切り替えても読んでいたビューは変わらない。** Kanboard 自身の切替は常にボードに
  着地するので、あるプロジェクトのガントチャートから離れると次のプロジェクトのボードに出ました。
  パレットのプロジェクト項目は現在のビューを引き継ぎ、今いるプロジェクトには印を付けます。
- **フォーカスリングはどこにもない。** Kanboard はほとんどのダイアログの最初の input に
  `autofocus` を付けるので、誰も触れないうちからダイアログを開いた瞬間にオフセットの光輪が
  出ていました。フォーカスを示すのは要素自身の枠線で、色はアクセント — `--ring` は
  `var(--primary)` として定義してあるので、ブランド設定をしたインスタンスはフォーカス状態にも
  その色が乗ります。リンクは色を付ける枠線がないので、代わりにアクセント色の下線を取ります。
  （フィールドにはそもそも*ホバー*状態もありません: ホバーと通常は同じ `shadow-xs` に
  計算されます。）
- **アイコンだけのボタンはグリフだけ** — 台座もパディングもなく、ホバーで動くのは色だけです。
  ダイアログの閉じるボタン、サイドバーのトリガー、トップバーの二つのメニューがこれにあたります。
- **Kanboard のビュー切替はサイドバーと同じことを言うようになった。** どちらも
  概要／ボード／リスト／カレンダー／ガントを提供します。切替そのものには手を付けていません。
  検索ボックスとフィルタのドロップダウンも載せていて、それらに他の居場所がないからです。
- **チャート以外の `!important` は一つ。** `core/modal.js` はビューポートを測ってダイアログの
  幅を要素に直接書き込みます。シートの幅はシートが決めるもので、そのサイズのダイアログなら
  こうだったはずの幅ではありません。だからインラインの値には負けてもらう必要があり、それに
  勝てるのは `width: … !important` だけです。
- **第 5 回でコンポーネント表を埋め切った。** デートピッカーとタイムピッカーは shadcn の
  Calendar に。アップロードシートには本物のドロップゾーンとファイルごとの行。添付画像は 4:3 の
  グリッドに、スライドショーの操作は丸いアイコンボタンに。修飾クラスのない `.alert` は Empty に。
  ショートカット一覧は Kbd のキーを表示し、二要素認証のコードは六つのスロットに。`toggle-on`／
  `toggle-off` はスイッチとして描き、サブタスクのあるカードには進捗バー、ドラッグ後に保存中の
  カードはスピナーではなくシマーに。うち二つはスタイルシートでは作れないマークアップが要るので、
  `Assets/js/widgets.js` がその場で組み立てます — OTP のスロットは元の input の*下*に敷くだけで、
  送信も自動入力も貼り付けも、受けるのはその input のままです。
- **右から左は変換ではなく鏡映。** Kanboard はアラビア語とペルシア語で `dir="rtl"` を設定します。
  コアのスタイルシートは物理プロパティで書かれているので、コアの `margin-left` の代わりに論理
  プロパティの `margin-inline-start` を置くと、RTL では右に付き、コアのものは左に残ります。
  `sidebar.css` 末尾のブロックは代わりに物理的な両側を設定し、詳細度を足さない
  `:where([dir="rtl"])` の下に置いています。鏡映ルールは元のルールと同じ詳細度なので、元を
  上書きしていたものは鏡映も上書きします。意図して物理のままにしたのは、時間と軸がどの言語でも
  左から右に流れるカレンダー・ガントチャート・チャート、jQuery UI が自分で鏡映するデートピッカー、
  そして矢印キーに従うスライドショーの前へ／次へボタン。タスク概要の色の辺だけは論理プロパティが
  正解です — コアはその色を四辺すべてに書くので、残る一辺が読む向きに従います。追従できないのは
  リスト行の色の帯で、コアはタスク自身の色で `border-left` として書き、読めない色をスタイルシートが
  動かすことはできません。
- **ページタイトルにはアプリケーション名が入る。** すべてのタイトルの末尾は **設定 → 外観** で
  設定した名前になり、コアが単に「Kanboard」とだけ書いていた画面ではその名前に置き換わります。
- **アイコンのパッケージは先へ進んでいる。** `@hugeicons/core-free-icons` 4.3.2 は、このテーマが
  出荷しているアイコンのうち十二個（user、users、home、link、copy など）を描き直しているため、
  それでジェネレーターを回すとそれらが変わります。第 5 回で必要になった三つのクラスは、コミット
  済みのセットの横に、既存の絵を流用して追加しました。
- `color-mix()` と `oklch()` を全体で使っています。どちらも 2023 年以降のブラウザが必要です
  （Chrome 111+、Safari 16.4+、Firefox 113+）。`:has()` の役割は今やもっと大きく、ページの
  グリッド全体が `body:has(> .sc-sb)` にぶら下がっているため、Firefox 121 未満ではサイドバーが
  ページ上部の普通のブロックとして描画されます — 元々の縦積みレイアウトそのもので、問題なく
  使えます。他の場所では `:has()` を三箇所で使っています — 完了したサブタスク行を淡くするため、
  そしてコメントの操作メニューとサブタスクのドラッグハンドルを、そのドロップダウンが開いている
  間だけ見せておくため — いずれも効果を足すためだけなので、Firefox 121 未満ではそれらの行が
  普段どおりの見た目のままになるだけです。
